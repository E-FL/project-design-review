Created by Arik Aizikovich. Fictional Morrow captures, on-screen callouts and local synthesized English narration. Setup, Ctrl visibility and connected-worker diagrams are explanatory illustrations; the demo worker is unconnected.

00:00:00.000  See the alternative. Decide with context.
Page-by-page Project Design Review by Arik Aizikovich. A concrete comparison workspace for Codex and Claude Code.

00:00:11.000  More than one annotation
Annotate points to an element. Here, inspect the current screen beside a concrete alternative, explain why, and preserve the decision and history.

00:00:23.000  Give the details in your request
Describe the project, products, platforms, language and review mode in the skill run. The agent manages setup; you do not edit configuration files.

00:00:36.000  Continue without repeating the setup
Project settings are remembered locally. Continue the review reuses the same board; Switch to Brief changes only the requested setting.

00:02:07.000  Appearance is a separate choice

00:02:18.000  Check Android within its own context

00:02:30.000  Then inspect iOS

00:02:42.000  Compare the PWA on par
Judge equivalent information, primary actions and outcomes across platforms. These platform screens are simulations, not physical-device validation.

00:02:55.000  Language follows your request
Ask for any review language, including RTL. The agent localizes generated content. A missing product-locale capture stays missing; it is never silently relabeled.

00:03:10.000  Flag the exact element or image
A numbered flag records the exact source image and revision. Hover or keyboard focus opens its RichTip: target, note and source context.

00:03:22.000  Pointing is optional
Keyboard placement lets you choose the side and normalized position. General notes can describe the whole page without any coordinate.

00:03:33.000  Keep the page-level conversation clear
Use a general page note for hierarchy, flow or overall direction. Save and Export remain together in the bottom-right controls.

00:03:44.000  See through your flags
The visible opacity slider ranges from zero to one hundred percent. Your chosen opacity persists across pages, revisions and reloads.

00:03:56.000  A temporary peek with Ctrl
Hold Ctrl to hide flags and RichTips. Release it to restore your saved opacity. This is a display preference, not an annotation edit.

00:04:09.000  Open either side at full size
The full-size viewer loads both sides in the same frame. Flip with the button or Space and F; arrows select a side; Escape returns.

00:04:21.000  Flip instantly, one on top of the other
Switch without a fade or layout shift. The shared scale, origin and pan make the difference easier to inspect; mismatched dimensions are disclosed.

00:04:33.000  Brief keeps the review compact
Brief shows comparisons, provenance, concise scope, feedback and decisions. It avoids generating long explanations that were never requested.

00:04:45.000  Full explains the elements below
Full adds what exists, what changes, why, what to keep, accessibility considerations, platform parity, status and unresolved choices. Saved details match their review revision.

00:05:01.000  Preserve every iteration
First, Back, Next and Latest stay inside one board. Older screenshots, flags, notes and decisions remain available under their own revision.

00:05:14.000  Discuss in context
Open a discussion about the page, a part or a flag. The right drawer keeps that exact context while you explain the requested change.

00:05:25.000  A request can queue the next pass immediately
Request these changes and start saves a bounded prototype request in one action. This unconnected demo correctly shows Queued, not Working.

00:05:37.000  Keep reviewing while real work runs
With a connected agent, a claimed request can run in the background. A verified result becomes a new immutable revision; explicit historical views and unsaved notes remain selected.

00:05:51.000  Preview the prepared visual source
A prepared source opens as a preserved interactive snapshot. Try the fictional controls, then return to the review. New requests need an updated source.

00:06:04.000  An interaction is still a prototype
This button responds inside the isolated preview. No live booking, account or payment action is connected. Previewing does not approve the design.

00:06:17.000  Approval has precise meaning
Approved as-is accepts the shown design without requested edits. This is a demonstration reviewer action on disposable fictional data.

00:06:28.000  Acceptance with changes is a distinct decision
Approved with changes records acceptance of an edit scope. Changes requested remains pending feedback, separate from work authorization and deployment.

00:06:40.000  Reject without losing evidence
Reject declines the proposal while keeping notes and previews. Reopen lets the review continue; it never changes the shipping product.

00:06:51.000  Share this exact review
The link includes page, feedback revision, source pair, capture axes and detail mode. A loopback link is local; copying it does not publish the board.
